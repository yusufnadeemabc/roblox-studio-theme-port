## 🎨 The Philosophy Behind the Palette

Every color in this collection was chosen with a simple question in mind: *“Does this reduce the mental cost of switching between Roblox Studio and VS Code?”*

Roblox Studio’s default environment leans toward a soft, slightly desaturated blue-gray palette with warm accents. VS Code, by contrast, is a chameleon — capable of anything, but neutral by default. This project treats that gap as an opportunity.

We studied:

- **Luminance contrast ratios** across dozens of common script patterns (Luau, TypeScript, JSON, Markdown).
- **Hue separation** between syntax categories (keywords, strings, functions, comments) to minimize visual hunting.
- **Saturation balance** so that long sessions do not fatigue the eyes, while still keeping important tokens distinct.
- **Ambient consistency** between the Explorer panel, the output console, and the editor canvas.

The result is a palette that feels *familiar* to Roblox developers, yet polished enough for full-time VS Code users who never open Studio. It is a bridge, not a wall.

## ✨ Feature Constellation

Below is a constellation of capabilities, each described from a *benefit-first* perspective — not just a bullet list, but a story of how it improves your daily workflow.

### 🌈 Responsive UI Harmony

The themes respond gracefully to window size, sidebar toggles, and split-view arrangements. Colors remain coherent whether you are on a 13-inch laptop or a 49-inch ultrawide. The aim is **visual stability** — no jarring shifts when you open a terminal or drag a panel.

### 🌍 Multilingual Support & Internationalization

Documentation, comments, and UI strings inside example files are provided in multiple languages (English, Spanish, Japanese, German, and Brazilian Portuguese). The theme itself is language-agnostic, but the *repository experience* is designed for a global audience — because code is a universal language, and so is the need for comfortable editing.

### 🕰️ Always-Available Guidance

Think of this repository as a **24/7 companion** — not a live chat, but a consistently available reference. The documentation is thorough, the examples are self-contained, and the issue templates are designed to get you answers quickly. Whether it is 3 AM or 3 PM, the guidance is here.

### 🧩 Semantic Token Intelligence

Modern VS Code uses semantic highlighting for richer distinctions. This theme includes carefully tuned semantic token colors for:

- Classes and interfaces
- Enums and enum members
- Namespaces and modules
- Type parameters
- Decorators and attributes

This means your code does not just look colored — it looks *understood*.

### 🌗 Dual-Mode Ambience

Two complete themes are included:

1. **Studio Nocturne** — a dark theme inspired by late-night building sessions, with deep navy-blues and muted teals.
2. **Studio Daylight** — a light theme that avoids the harsh “paper white” trap, using warm off-whites and soft slate grays.

Both are available separately and can be switched without restarting the editor.

### 🪄 Zero-Config Comfort

No build steps. No dependency graphs. The theme files are plain JSON, ready to be placed into your editor’s extension folder or packaged as a VSIX. This is intentional — *themes should be simple to adopt and simple to modify.*

## 🧪 Technical Composition

### Theme Architecture

The repository is organized into two primary theme JSON files, each carefully structured:

- `themes/studio-nocturne.json` — the dark variant.
- `themes/studio-daylight.json` — the light variant.

Both files follow the VS Code theme schema and include:

- `colors` — for workbench UI elements (activity bar, side bar, editor background, etc.).
- `tokenColors` — for syntax highlighting.
- `semanticTokenColors` — for semantic highlighting.
- `semanticHighlighting` — enabled where supported.

### Compatibility Matrix

| VS Code Version | Support Status |
|----------------|----------------|
| 1.70 – 1.79 | Partial (no semantic tokens) |
| 1.80 – 1.89 | Full syntax, partial semantic |
| 1.90 – 1.99 | Full support |
| 2.00+ (2026 builds) | Full support, tested |

### Performance Notes

- Theme files are static JSON — no runtime overhead.
- No background processes or extensions are required beyond the theme itself.
- Startup impact is negligible; the editor loads colors as part of its normal initialization.
